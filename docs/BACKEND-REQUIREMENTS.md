# 后端需求基线与纠偏计划

日期：2026-10-28（Asia/Shanghai）。状态：设计与只读审查结论，不代表功能已实现或交付已验收。

## 1. 用户确认的目标与边界

- 以 Codex 为主要工程执行器，主要使用经过验证的经济模型与专家模型；DeepSeek 经济模型、基础 ChatGPT 对话及人工承担合适的辅助工作。
- 优化验收成功任务的总成本：分别记录 API 实际花费、订阅额度消耗、失败重试和人工耗时。少 token 不等于总成本一定更低。
- 引入现有 Jev 决策模型。所有任务必须先判断适合的执行者，判断结果需要能够追溯。
- 长实验由独立程序执行；等待、健康检查、完成事件和额度等待不调用模型。额度中断不得造成任务身份、成果或已完成阶段丢失，不能重复启动状态不明的计算。
- 模型与策略持续更新；工程错误必须产生有证据、有范围、有验证和可撤销的纠正措施。
- 用户已明确要求：本地 Git 检查点，并自动同步到指定私有远端。远端地址尚未提供，当前没有创建或推送仓库的目标。
- Google 与 Grok 额外订阅是候选，未选定购买或接入；不能自行启用新增支出。
- 先完成后端；不再更新版本号，编程品味与技术栈细节由用户后续补充。本轮暂停 GUI 与打包工作，先校正后端设计。

## 3. Jev 与模型分工设计

Jev 是 TypeSafe 的现有结构化决策模型，不负责写代码、对话或执行工具。官方当前版本为 `jev-1.14.0`；官方公布按输入 token 计费，输出免费，英文是其效果最佳的主要训练语言。中文任务的路由准确性与置信度阈值必须独立验证，不能把结构化输出视为判断必然正确。

来源：[Jev 与编程智能体](https://docs.typesafe.ai/introduction/coding-agents)、[模型、价格与语言边界](https://docs.typesafe.ai/models)。

建议的数据流：

1. 固定目标、验收条件、项目和数据范围。
2. 程序先约束执行能力、权限与预算，再判断能否直接使用脚本或人工流程。
3. 需要语义判断时，只将必要任务特征交给 Jev，在一次请求中回答任务类型、难度、影响范围等原子问题；程序综合结果，记录理由、模型、输入预算、验收与升级条件。
4. 写执行前由受控后端保存并验证检查点，再派发执行；模型不得扩大权限或跳过检查点。
5. 验收后记录实际成本和效果，形成可用于后续路由评估的样本。

| 执行者 | 负责的工作 | 使用约束 |
| --- | --- | --- |
| 确定性程序 | 计算、测试、转换、等待、备份与状态核对 | 无需为这些工作持续调用模型 |
| 基础 ChatGPT / 人工 | 澄清、基础文字整理、必要授权与判断 | 明确交接包、待办和完成证据；不假装已通过免费接口自动执行 |
| DeepSeek 经济模型 | 有清晰输入输出的辅助分析、批量文本任务 | 先作为受限文本处理器；需要写文件时可提出补丁，由受控执行器应用和验证，不能假称文本 API 已有工具执行能力 |
| Codex 经济模型 | 边界清楚、重复或可验证的工程工作 | 以当前账号可用模型与代表性任务评估确定 |
| Codex 专家模型 | 高难根因、架构决策、关键风险审阅 | 按风险或验证失败触发，限制返工与升级次数 |

官方当前目录将 `gpt-6-luna` 定位为高频明确任务的经济候选，将 `gpt-6-astra` 定位为复杂任务的专家候选；`gpt-6.1-sol` 可作为复杂重复工程的中间候选。DeepSeek 当前目录的 `deepseek-flash` 可作为经济候选。它们只是评估起点，不代表已证明最适合用户，且未改正式模型配置。

来源：[Codex 官方模型目录](https://learn.chatgpt.com/docs/models?surface=cli)、[DeepSeek 当前型号与价格](https://api-docs.deepseek.com/quick_start/pricing/)。

为降低路由自身开销，建议由确定性规则直接处理已明确的判断，语义不确定时使用 Jev。Jev 结果按任务阶段、输入摘要哈希和策略版本缓存；不因重开聊天而重复判断全部任务。先用中文历史任务与事故案例比较规则基线和规则加 Jev 的效果，再启用实际付费判断。模型升级使用固定候选版本、相同验收样本和可回退配置，不直接追随 latest 别名。

## 4. 长计算与限额接续设计

阶段应明确拆为：计划与改码 → 注册独立实验 → 普通程序等待 → 固化成果 → 分析 → 验收。

- 实验注册必须保存命令参数、代码检查点、输入标识、成果位置和接续动作。
- 智能体提交实验后结束本轮推理，任务进入 WAITING_JOB；后台程序原生等待结果。
- 五小时额度限制仍可能结束模型轮次；计算和任务记录必须保持独立。模型额度恢复后，先核对真实进程、Git 状态和成果，再接续保存的 session。
- session 不可用时，沿同一 Task 的已验证阶段与成果建立新执行尝试；不重新开始实验或重复已完成阶段。
- UNKNOWN 必须先核对；不能通过换键、换模型或换聊天绕过。
- 同项目写入串行；仅在有隔离与明确合并协议时增加并行，不能默认多智能体重复分析同一工作。

## 5. 本地 Git 与私有远端同步

Git 保护代码、文档、规则和允许的小文本成果；实验大文件、数据库、应用会话及凭据需要分别处理。`.gitignore` 排除的数据不会因此获得备份，私有仓库也不应接收凭据。

1. 审阅入口默认只读。写任务在受限工作副本中执行，执行者没有对用户主目录、智能体状态根和检查点库的写权限。项目路径和工作目录校验不能替代操作系统权限隔离。
2. 写执行前保存包含授权代码、已有暂存/未暂存改动及允许的新文件的检查点；保留用户原分支、索引和工作状态。检查点库由受控后端管理，放在执行者不可删除的范围。
3. 检查点必须有 Task/Job 关联、覆盖/排除清单、内容哈希和成功回执；检查点失败时不启动写任务。
4. 自动同步到用户指定私有远端。记录待同步、成功和失败状态；网络失败不丢弃本地检查点，也不能显示为上传成功。远端或本地身份改变时停止并核对，不静默替换已有 origin。
5. 凭据、数据库、运行日志和会话不进入普通源码仓库；有价值的非 Git 数据使用一致性快照、加密独立备份及成果清单。异盘或异地副本与同盘另一分区应明确区分。
6. 恢复先在新位置核对内容和差异，再提出可审查的恢复操作；不自动重放旧执行队列或覆盖当前成果，不用清空目录作为修复手段。

自动远端同步的必需配置仍缺少：具体私有远端 URL 和上传范围。非 Git 数据的独立备份目的地亦未指定。不得凭空创建云仓库或将所有本地数据上传。

## 6. 后端实施顺序与验收门槛

| 顺序 | 必须交付 | 通过条件 |
| --- | --- | --- |
| 1 安全与恢复基线 | 只读审阅、受限写执行、受保护检查点、私有同步状态与恢复路径 | 受保护测试数据不能被执行者越界写入；脏工作区和新文件能还原；本地保存失败阻止执行；离线明确显示未同步 |
| 2 任务连续性 | 阶段状态、独立实验、精简接续包、额度恢复 | 断开聊天与额度耗尽时实验继续；恢复只核对一次实际执行；保存的结果只分析，不重跑实验 |
| 3 Jev 与执行者分工 | 真实能力目录、决策记录、受控派发、人工交接回执 | 明确任务路由到合适执行者；误路由可追溯；中文样本达标；路由自身成本计入总成本 |
| 4 持续纠错与更新 | 故障证据、候选措施、回归、局部启用、撤销和路由评价 | 同类后续任务应用已验证措施；错误规则可撤回；升级不改变运行中的实验或已有身份 |

至少完成一条真实可验证的后端纵向流程，再讨论界面与交付标签。以上均为后续工程计划，本轮没有将计划写成已实现。
