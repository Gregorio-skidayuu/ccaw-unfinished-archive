# 恢复与纠错操作约定

## 数据与状态

一个 Job 同时代表一次实际执行尝试；相同 Task 下可有多个阶段或不同模型的 Job。Task、Job、Lesson 的身份不会因重新打开终端改变。

Job 状态为 QUEUED → STARTING → RUNNING → SUCCEEDED / FAILED / CANCELLED / WAITING_CAPACITY。无法核对执行者时进入 UNKNOWN。UNKNOWN 阻止同项目派发，不意味着计算已停止。

SUCCEEDED 证明脚本退出为 0，或 Codex 正常完成一轮，或 API 返回完整文本；任务进入 VERIFYING，最终仍需按验收条件确认。启动过、进程退出过或输出过文字都不足以单独证明任务完成。

启动意图先提交数据库，再创建 worker；worker 以事务领取。启动后崩溃产生的未知窗口由 UNKNOWN 处理，不能靠重新启动“修复”。完成事件和接续键可去重，不承诺所有外部副作用恰好执行一次。

worker 在子进程仍存活或无法确认退出时遇到异常，也会保留 UNKNOWN，不能把内部错误当作实际计算失败。Codex JSONL 中非对象的 JSON 行会跳过，完成仍须核对实际协议事件。

API 已发出请求但传输/解码失败或响应格式不兼容时，同样进入 UNKNOWN，费用记录标为 UNCERTAIN 并保留预留。先核对供应商记录与账单，再通过 `job resolve` 确认结束；该操作不会自动释放预留。若完成文本明确但未返回用量，作业可成功，费用仍保留预留。当前没有账单对账和预留调整命令，不要通过删除数据库或更换项目路径绕过预算。

## 出错时

1. 保存原命令、版本、预期与实际结果以及最小证据；不要把密钥写入故障记录。
2. 区分代码、工作流、模型能力、需求、外部环境和验证方法错误。
3. 优先恢复当前工作，保留可用的计算成果；原因不明时保持待确认。
4. 修复代码或运行器等实际根因。需要复用的措施使用 incident / lesson 命令建立记录。
5. 运行有针对性的回归验证，再启用对应项目和标签范围的经验。
6. 后续复发时重新检查根因与覆盖范围；错误经验先撤回，再修订、验证、启用。

经验状态为 CANDIDATE → VERIFIED → ACTIVE → REVOKED。修订增加版本并退回 CANDIDATE，旧验证不自动沿用。已撤回经验不会进入新任务包；旧执行快照仍保留当时的经验版本。

经验匹配目前使用同一项目的绝对路径及显式标签；移动项目后应核对任务与经验，不会自动扩大到新目录或全局。近期复发次数由相同项目和 signature 的新 incident 累计，作为观察信号而非自动根因结论。

## 低成本运行原则

路由和检索不调用模型；计算等待只使用普通进程。没有配置可用的模型映射时明确使用 Codex 本机默认，而非假装已自动找到性价比最高型号。一般故障复用现有上下文；复杂和高风险根因才升级模型。

正常故障不创建新的全量测试流程。只有有合理复发可能的缺陷才增加长期防护；复盘投入和错误阻断产生的额外时间同样属于成本。

## 额度恢复自动继续（v0.2）

只有 `job agent --auto-resume` 创建的作业获得授权，旧作业与普通执行默认不变。首次启动先用官方 app-server 额度读取接口绑定当前订阅账号；预检失败记为 `AUTO_RESUME_SETUP`，不启动模型，也不误当作额度耗尽进行重试。

授权、账号、等待期限、接续和撤销记录使用现有 SQLite events；原始执行指令保存在初始作业快照中。每次自动接续的键为 `capacity:<原作业ID>`，快照保留根作业、父作业、账号与刷新周期。数据库及配置 schema 仍为 1，不需要迁移，也不改写旧记录。

每条授权链只有一个普通后台等待进程，使用 Windows 文件锁或 Linux flock 排除重复等待者。等待期限持久化，重启 `job watch` 不会绕过检查间隔。进程存活、停止和下次检查可通过 `job show` 的 `diagnostics.auto_resume` 查看，日志位于该字段的 `log_path`。

当前接口读取 `codex` 额度桶。许可字段必须明确为真，账号及窗口周期也必须可核对；百分比降低或到达预估重置时间均不能单独证明额度恢复。不支持明确许可字段的旧版 CLI 会保留等待。后台查询不创建 thread/turn、不消费重置券、不发送邮件，也不切换付费服务。

自动入队与派发分别核对授权、任务状态、原 session、项目活动作业和当前角色；`task done` 的未完成作业检查与验收写入也放在同一事务中。已持久化的 QUEUED 自动后继恢复时重新读取额度；账号、角色或周期变化会撤销旧授权、取消尚未派发的自动队列，并要求人工核对。STARTING/RUNNING/UNKNOWN 不会被当作未执行队列重新派发。

`job unwatch` 撤销整条恢复链的后续自动继续，取消 QUEUED 自动后继；不会取消已运行的计算。`job cancel <当前JOB_ID>` 同时撤销恢复链并按原有规则请求取消该 Job。原始 WAITING_CAPACITY 作业保留真实历史状态，不能仅凭原始状态判断后继是否已运行；请查看 `current_job_id/current_status`。

同一窗口最多一次自动尝试。再次限额时等待新的明确周期信号；成功后进入 VERIFYING，仍需人工按验收条件确认任务。机器重启后可运行 `job watch` 恢复等待，本版本未安装操作系统开机服务。真实模型额度耗尽—重置—恢复全链路尚需实际接入验收，本地回归使用假执行器；本机已完成无模型的真实额度读取核验。

## 更新

配置以完整 JSON 为来源，保留内容哈希历史和递增 revision。执行时锁定配置和已注入经验版本；更新只影响后续执行。read-only 沙箱收紧或 API 禁用在下一次实际派发前重新检查。

数据库 schema_version 当前为 1。未知版本拒绝打开写入，不自动破坏性迁移。更改数据格式前增加显式迁移并验证备份恢复；回退程序不应删除实验结果或恢复用户代码的旧版本。

## 凭据

不要提交 `.ccaw`、`.env`、`auth.json`、训练日志或实验检查点。运行目录含命令与任务包；同样不要把密钥当作脚本参数或提示词。Codex 凭据由 Codex 自身管理；CCAW 不复制登录文件，也不把订阅登录转成其他服务的 API 密钥。
